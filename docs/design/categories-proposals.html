Proposal 1 · closest to today

Quiet rows, actions on hover

Same nested tree, but the 4-button cluster collapses. Primary action (add child) stays a ghost icon; rename / move / delete fold into a ⋯ menu. Buttons only paint on row hover or keyboard focus, so the page reads as data first. Each leaf gains the number it was missing plus a share bar against its parent.

  • smallest diff from current code
  • leaf amounts visible
  • hover-only actions need a touch fallback

Proposal 2 · restructure

Two-pane: tree on the left, one category at a time on the right

The list becomes navigation only — icon, colour, name, total. Every mutating action lives in the detail pane for the selected node, so there is exactly one set of buttons on screen instead of 26. Scales past 50 categories without the page getting longer, and gives room for stats (transaction count, monthly average, last used) the current row can't hold.

  • one action set, always in the same place
  • scales to deep/wide trees
  • two clicks to act on a node
  • biggest rewrite

Proposal 3 · data-first

Dense table with collapsible groups

Treats the page as what it mostly is: a ledger of totals. Aligned tabular-nums column, share of parent, transaction count, and collapsible folders so a 60-category tree fits one screen. Row actions are hover icons pinned to a fixed-width column so nothing reflows.

  • densest — most categories per screen
  • columns are comparable at a glance
  • feels administrative, less "shape of spending"

Proposal 4 · visual

Cards, one per root category

Each root is a card sized by nothing but content, with its colour as a top rule and its children as mini bars. Grid reflows, so wide screens show 3 across instead of one long column with 2000px of dead space to the right — the main flaw of the current layout. Actions sit in a card footer, one row per card rather than one row per node.

  • uses horizontal space
  • colour + proportion legible instantly
  • deep nesting (3+ levels) needs a drill-in
