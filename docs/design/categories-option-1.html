Nesting

How each depth is drawn

Indent is linear, everything else is not: only two typographic weights exist (root vs. everything below), so a depth-5 tree doesn't fade to nothing. Depth is carried by the indent and a faint background tint, not by ladder lines and not by shrinking the text — the lines competed with the row borders and turned the card into graph paper.

Past the cap both the indent and the tint stop stepping, so a pathological 12-deep branch stays inside the card instead of pushing the amount column off-screen. In CategoryNode this is one depth prop threaded through the existing recursion — the recursion itself is unchanged.

Keyboard & a11y

The tree is one tab stop, not sixty

Hover-revealed actions are only acceptable if the keyboard reaches them without hovering. Rows form a roving-tabindex tree (role="tree" / treeitem), so Tab enters the tree once and arrows walk it — the same pattern the IconPicker grid already uses.

KeyDoes
↑ ↓previous / next visible row
→expand a collapsed folder, else step to its first child
←collapse an expanded folder, else jump to its parent
Enteropen the row's transactions (/categories/$categoryId)
F2rename the focused row
Shift+Nadd a child under the focused row
⋯ / Shift+F10open the row menu; arrows walk it, Escape returns focus to the trigger
Home / Endfirst / last visible row
type letterstypeahead to the next row whose name starts with them

Because .actions reveals on :focus-within as well as :hover, arrowing to a row and tabbing into it shows the same two buttons a mouse user sees. Coarse pointers (@media (hover: none)) get them permanently — there is no hover to wait for on a phone.

Implementation

What actually changes in categories-view.tsx

The recursion, the totals query, the colour resolution and the whole dialog stack are untouched. The diff is concentrated in two components.

UnitChange
CategoriesViewunchanged, except <ul> gains role="tree" and the roving-focus state
CategoryNodetakes a depth prop; folders below depth 0 render as a row + nested list instead of a fieldset; gains expanded state and the chevron
NodeControlsrewritten: one icon button + a Base UI Menu. Same four callbacks, no new props
NodeIdentitygains the inherited/chosen swatch distinction — it already receives both node.color and the resolved colour, so no new data
new CategoryRowthe shared row shell (indent, depth tint, identity, bar, money, actions) both kinds render through
new use-category-totalsleaf totals: today only folders get a transactionQueries.count. Leaves need one each — same endpoint, categoryId: [leaf.id]
categories-view.test.tsxthe button-per-row queries (Rename Food etc.) now resolve inside the menu; tests open ⋯ first

The one real cost: leaf amounts mean one count query per leaf instead of one per folder. With 30 categories that is 30 requests where there were 6. Either batch it server-side (a totals endpoint keyed by category, which the transactions count shape already almost is) or accept it — TanStack dedupes and they are all cached under the same key family. Worth deciding before building.
